# topcoat-graph docs site: implementation plan

**Goal:** Rebuild `site/` as a docs website modeled on `../topcoat-prompt/site`.
**Spec:** `docs/superpowers/specs/2026-11-26-docs-site-design.md`
**Execution:** hybrid, as before. Opus subagents do tasks 1 and 3; Fable does 2 and 4.

## Global Constraints

- Topcoat 0.12.1; use the CLI at `target/topcoat-cli/bin/topcoat`, never the global one.
- Edit chart components only in `crates/topcoat-graph/registry/components/`, then run
  `./scripts/sync-site.sh`. `site/src/components/` copies are never edited by hand.
- Colors only from theme tokens. Works in light and dark, and at phone width.
- No user-visible English inside registry components. Site prose is fine.
- Checks that must pass: `cargo test --workspace`, `cargo clippy --workspace
  --all-targets -- -D warnings`, `cargo fmt --check`, `rustfmt --check --edition 2024
  crates/topcoat-graph/registry/components/*.rs`, `topcoat fmt --check` in `site` and
  `crates/topcoat-graph`.
- Voice for all prose: plain, direct, no filler, no hype words.

## Review Focus

1. A chart page with no script: previews, code and tables still render.
2. Playground state that the browser sends is untrusted: out-of-range numbers and
   unknown choices fall back to defaults, never panic.
3. Two playgrounds or examples on one page never share signal or element ids.
4. Phone width: sidebar sheet works, tables and code scroll inside their box, charts
   keep their shape, no page-level horizontal scroll.
5. The code a playground shows compiles as written and draws what is on screen.

## Task 1: site skeleton (Opus)

Port shell, catalog, docs page, API tables, highlighting, prose pages, `llms.txt`,
deploy files. Move every gallery example into `site/src/examples/<chart>_<name>.rs`.
Keep all render tests passing against the new URLs (`/docs/<component>`).
Produces: `catalog::{ComponentDoc, Example, COMPONENTS}` with
`playground: Option<fn(&Cx) -> BoxView<'_>>` (all `None`), rendered above the examples
when present; `shell` helpers for a bordered preview panel and a highlighted code panel
(`shell::code_panel(source: String)` or the ported equivalent).

## Task 2: playgrounds (Fable)

`site/src/playground/{bar,line,area,pie}.rs`, each a `#[shard]` with one signal per
control, sanitized inputs, the chart, and generated code. Tests: each chart page has a
playground; the default code matches the default chart; generated code for each option
set is covered by unit tests of the pure `code(options) -> String` functions.

## Task 3: blocks (Opus, in a worktree, alongside task 2)

`/blocks` with the six blocks from the spec, each a file under `site/src/examples/`
named `block_*.rs`, with Preview | Code. Render tests per block.

## Task 4: review, browser pass, CI (Fable)

All checks, a Chrome pass in light and dark and at phone width over home, two chart
pages, a part page, blocks and playgrounds, console clean, Docker build if practical,
push, CI green. Then a fresh whole-branch review and one fix pass.
